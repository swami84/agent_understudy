# WhatsApp corpus

`raw/`      — drop WhatsApp "Export chat" files here (.txt or .zip).
`chats/`    — parsed, session-chunked markdown. Generated.
`people/`   — per-person profile cards. Generated by local LLM.
`groups/`   — per-group context cards. Generated by local LLM.
`timeline/` — dated timeline cards, per chat and per person, plus `_now.md`
              (today's date — nothing else tells the model what day it is).
`locations.md` — who is based where, grouped by city. Generated by local LLM.
`.manifest.json`, `.cache/` — build ledger and the per-month extraction cache.
              Deleting `.cache/` forces every month back through the model.

Everything here is gitignored except this file. The rule is an allowlist
(`corpus/*` + `!corpus/README.md`), so a stage added later is private by default
rather than needing someone to remember a new ignore line.

Both `chats/` and `people/` are indexed into OpenClaw memory via
`memory.search.extraPaths`, so retrieval works over them with no extra vector DB.

## Getting history out of WhatsApp

There is no local back-catalogue — the Baileys auth dir holds only crypto state,
and the plugin sets `syncFullHistory: false`. Use WhatsApp's own export:

  phone -> open chat -> ⋮ / contact name -> Export chat -> Without media

"Without media" is strongly preferred: media exports are enormous and the parser
records attachments as `[media]` regardless.

## Getting names for group members

WhatsApp gives phone numbers, not names — participant records carry only
id/lid/phoneNumber, and the contacts store isn't synced on reconnect. Export your
address book and match by number:

  iOS      icloud.com -> Contacts -> select all -> gear -> Export vCard
  Android  Contacts app -> Settings -> Export -> .vcf
           (or contacts.google.com -> Export -> vCard / Google CSV)

    python3 ingest/import_contacts.py corpus/raw/contacts.vcf          # dry run
    python3 ingest/import_contacts.py corpus/raw/contacts.vcf --apply  # write

Matching compares the last 10 digits, because address books routinely omit the
country code while WhatsApp always includes it. Numbers that map to more than one
contact are reported as ambiguous and left alone rather than guessed.

## Pipeline

    # 1. parse exports -> session-chunked markdown
    python3 ingest/parse_export.py corpus/raw/*.txt corpus/raw/*.zip

    # 2. build per-person cards on local GPU (slow; run over a coffee)
    python3 ingest/build_profiles.py --min-messages 30

    # 3. group rosters (allowlisted groups only; gateway must be stopped)
    systemctl --user stop openclaw-gateway.service
    node ingest/extract_group.mjs
    systemctl --user start openclaw-gateway.service

    # 4. reindex
    openclaw memory index --force --agent main

## Notes

- Your own name will appear as a "person". Skip it, or build it deliberately and
  fold the result into `~/.openclaw/workspace/USER.md`.
- `--gap` (default 45 min) controls what counts as one conversation. Raise it for
  slow-moving chats, lower it for busy ones.
- Profile cards are model-derived. They are a retrieval aid, not a record.
